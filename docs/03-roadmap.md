# 03. Дорожная карта (чек-лист этапов)

> Сначала выполняется MVP из `08-mvp-plan.md`. Эта карта: полная версия после MVP.

Отмечай `[x]` по мере выполнения. Каждый этап = рабочий результат + тесты + коммит. Подробные правила прохождения: `00-master-plan.md`.

## Фаза 1. Основа
- [ ] **0. Репозиторий и окружение.** Монорепо (`apps/web`, `apps/api`, `apps/worker`, `templates`, `knowledge`, `infra`), Docker Compose (postgres, redis, minio, mailpit), `Makefile` (`dev`, `test`, `lint`), `.env.example`, CI-скелет (GitHub Actions), pre-commit (gitleaks, линтеры). *Готово, когда:* `make dev` поднимает всё, `/healthz` отвечает.
- [ ] **1. Дизайн-система и каркас фронта.** Токены из `05-design-system.md`, базовые компоненты, лэйаут, главная-заглушка, тёмная/светлая тема. *Готово, когда:* страница открывается, Lighthouse a11y ≥ 90.
- [ ] **2. Формат шаблонов.** Схема YAML (поля, роли, условия, валидаторы), загрузчик + валидатор, эталонный шаблон «Трудовой договор». *Готово, когда:* тесты валидатора зелёные.
- [ ] **3. Движок рендера.** Данные + шаблон → текст → DOCX → PDF (воркер с LibreOffice в отдельном контейнере). Тесты на золотых файлах. *Готово, когда:* эталонный договор скачивается в обоих форматах.

## Фаза 2. Продукт без ИИ
- [ ] **4. Аккаунты.** Регистрация/вход (argon2id, cookie-сессии, подтверждение email), сброс пароля, rate limit. *Готово, когда:* e2e вход/выход, тесты на брутфорс.
- [ ] **5. Каталог и анкета (режим A).** Каталог (SSR/ISR), страница шаблона, динамическая анкета по шагам, живой предпросмотр, автосохранение черновика, скачивание **только после входа**.
- [ ] **6. Мои документы.** Список, повторное открытие, дубликат, удаление, история версий. Проверка владельца на каждом запросе (тесты IDOR).
- [ ] **7. Карточки сторон (режим B).** CRUD карточек (физлицо/ИП/организация), подстановка в роли, валидаторы ИНН/ОГРН/БИК/СНИЛС, шифрование чувствительных полей.
- [ ] **8. Наполнение шаблонов, часть 1.** 6 шаблонов (трудовой, ГПХ/услуги, аренда, купля-продажа, займ/расписка, доверенность), все `draft`.

## Фаза 3. ИИ
- [ ] **9. ИИ-слой.** Интерфейс `LLMProvider` (Anthropic), стриминг (SSE), квоты на пользователя и общий потолок расходов, логирование стоимости, защита от prompt injection, заглушка провайдера для тестов.
- [ ] **10. База норм (RAG).** Загрузка текстов ТК РФ, ГК РФ и др. в `knowledge/`, нарезка, pgvector, поиск; проверка ссылок на статьи.
- [ ] **11. ИИ-чат.** Чат по нормам в контексте документа + публичный чат для гостей с жёстким лимитом; ответы со ссылками, пометка «не подтверждено».
- [ ] **12. ИИ-редактор.** «Сделать в пользу стороны», «добавить пункт», «смягчить»: структурированные правки, diff с принять/отклонить, история.
- [ ] **13. ИИ-извлечение данных.** Вставка реквизитов текстом → поля с подтверждением пользователем.
- [ ] **14. Проверка чужого договора.** Загрузка DOCX/PDF (ClamAV, изоляция), список рисков.

## Фаза 4. Нагрузка, надёжность, безопасность
- [ ] **15. Асинхронность.** Очередь и воркеры для рендера и ИИ, идемпотентность, повторы, dead-letter, прогресс в интерфейсе.
- [ ] **16. Кэширование и производительность.** Кэш каталога, индексы, PgBouncer, профилирование, нагрузочные тесты k6 (цели в `07-…`).
- [ ] **17. Наблюдаемость.** OpenTelemetry, Prometheus, Grafana, Loki, алерты, Sentry, `/readyz`, дашборды.
- [ ] **18. Безопасность.** Заголовки/CSP/HSTS, CSRF, аудит зависимостей и образов в CI, SAST, секреты, пентест-чек-лист OWASP ASVS, 2FA (опц.).
- [ ] **19. Юридический слой.** Политика ПДн (152-ФЗ), пользовательское соглашение, согласия, cookie-баннер, дисклеймеры, удаление аккаунта и данных.

## Фаза 5. Контент и запуск
- [ ] **20. Наполнение шаблонов, часть 2.** Довести до 10-15 шаблонов.
- [ ] **21. Юридическая проверка** (делает человек, не Claude): шаблоны `draft` → `reviewed`.
- [ ] **22. Деплой на сервер (стадия S).** Сервер в РФ, Traefik + TLS, бэкапы + тест восстановления, мониторинг, firewall, CI/CD.
- [ ] **23. Отказоустойчивость (стадия H).** Реплика БД, несколько узлов, rolling-деплой, учения по восстановлению. Делается, когда трафик это оправдывает.
- [ ] **24. Запуск.** E2E на проде, нагрузочный тест, чек-лист готовности, аналитика.

## Зависимости
0 → 1,2 → 3 → 4 → 5 → 6,7 → 8. ИИ (9-14) после 5. 15-18 можно начинать после 5, обязательно до 22. 19 и 21 обязательны до публичного запуска.
