# 04. Архитектура (предложение)

> Нагрузка, очереди, отказоустойчивость и безопасность подробно: `07-infrastructure-and-security.md`. Это мои предложения, не решения. Стек выбран под ваш опыт (Go, Java) и простоту. Меняется по согласованию.

## Стек
- **Бэкенд:** Go (chi или gin), PostgreSQL, миграции через goose, sqlc или pgx.
- **Фронтенд:** Next.js (App Router) + TypeScript + Tailwind, компоненты на Radix/shadcn.
- **Генерация документов:** шаблоны в собственном формате → текст → DOCX (заполнение DOCX-шаблона или сборка) → PDF через LibreOffice headless.
- **ИИ:** Anthropic API через собственный интерфейс `LLMProvider` (легко заменить). Ключ только на сервере.
- **Поиск по нормам (RAG):** тексты ТК РФ, ГК РФ и др. в Postgres + pgvector; ответы ИИ должны ссылаться на найденные фрагменты.
- **Инфраструктура:** Docker Compose, затем VPS в РФ (из-за ПДн, 152-ФЗ). Redis для лимитов (позже).

## Структура репозитория
```
constructor-site/
  CLAUDE.md
  docs/                 # эти файлы
  apps/
    web/                # Next.js
    api/                # Go
  templates/            # шаблоны документов (YAML) + золотые файлы тестов
  knowledge/            # тексты норм для RAG
  infra/                # docker-compose, миграции
```

## Модель данных (черновик)
- `users`, `sessions`
- `parties` (карточки: тип, реквизиты JSONB, владелец)
- `templates` (slug, версия, категория, схема JSONB, статус проверки юристом)
- `documents` (владелец, шаблон+версия, данные JSONB, статус)
- `document_revisions` (история, в т.ч. ИИ-правки как diff)
- `ai_conversations`, `ai_messages`, `ai_usage` (лимиты и стоимость)
- `norm_chunks` (текст нормы, источник, статья, embedding)

## Формат шаблона (идея)
```yaml
slug: trudovoy-dogovor
title: Трудовой договор
roles: [employer, employee]        # роли под карточки сторон
fields:
  - id: employer.name   type: text   role: employer  required: true
  - id: probation       type: toggle
  - id: probation.months type: number  showIf: probation  max: 3
body: |
  ТРУДОВОЙ ДОГОВОР № {{number}} ...
  {{#if probation}} Испытание: {{probation.months}} мес. {{/if}}
```
Условные блоки, роли, валидаторы (ИНН, ОГРН, даты), версионирование.

## ИИ: как устроено безопасно
- Модель получает: выбранный документ, роль пользователя, найденные нормы. Не получает чужие данные.
- Правки приходят **структурированно** (JSON: операции над пунктами), бэкенд применяет их и показывает diff.
- Ссылки на нормы валидируются по `norm_chunks`; если нормы нет в базе, ответ помечается «не подтверждено».
- Лимиты на пользователя/IP, потолок токенов, логирование стоимости.
- Защита от prompt injection: загружаемый текст договора считается данными, не инструкциями.
- Везде дисклеймер: не заменяет юриста.

## API (эскиз)
`GET /templates`, `GET /templates/{slug}`, `POST /documents`, `PATCH /documents/{id}`, `POST /documents/{id}/render?format=docx|pdf`, `CRUD /parties`, `POST /ai/chat` (SSE), `POST /ai/edit`, `POST /ai/extract`, `POST /ai/review`.

## Тесты
Золотые файлы рендера, юнит-тесты валидаторов, контрактные тесты ИИ-слоя с заглушкой провайдера, E2E (Playwright) для сценария «выбрать шаблон → скачать».

## Отклонения от стека (MVP)
- **sqlc не используется:** запросы на pgx вручную (немного таблиц, без шага кодогенерации). Вернуть sqlc можно без изменения схемы.
- **Web → API через rewrites Next.js** (`/api/*` → Go): cookie сессии first-party, CORS не нужен.
- **Шаблоны в собственном мини-формате** (`{{field}}`, `{{#if}}`), без исполнения кода; рендерит только Go, фронт получает готовые блоки (единый источник правды для предпросмотра, DOCX и ИИ-правок).
