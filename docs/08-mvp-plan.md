# 08. MVP-план «договор.ai»

> **Это первый файл для запуска.** Цель: быстро показать рабочий MVP. **Функционал урезан, дизайн финальный** (то есть выглядит как готовый продукт, а не черновик). Всё остальное из `03-roadmap.md` делается после MVP.
> Название проекта: **договор.ai** (латиницей в коде: `dogovor-ai`).

## 1. Что показываем на демо (сценарий приёмки)
1. Открывается красивая главная: поиск/поле «какой документ нужен?», анимация закрепляющихся тем при прокрутке (см. п. 5).
2. Каталог → «Трудовой договор» → **режим А**: анкета по шагам, справа живой лист документа.
3. **Режим B**: «Заполнить по карточке» подставляет данные работодателя и работника из сохранённых карточек (или из вставленного текста с реквизитами, разбор делает ИИ).
4. **Режим C**: справа панель ИИ. Вопрос по нормам (ответ со ссылкой на статью) и команда «сделай в пользу работодателя» → ИИ предлагает правки, **diff с кнопками принять/отклонить**.
5. Кнопка «Скачать .docx» (и PDF, если получилось с LibreOffice). Гостю предлагается войти: **email + пароль или Яндекс ID**.
6. Личный кабинет: мои документы, мои карточки. Красивый, как референс `design/v2.jpg`.
7. Публичный ИИ-чат на главной со счётчиком «осталось N бесплатных вопросов».

## 2. Что входит и что НЕ входит в MVP

| Входит | Не входит (после MVP) |
|---|---|
| 6 шаблонов: трудовой, оказание услуг (ГПХ), аренда жилья, купля-продажа, расписка/займ, доверенность | 800+ шаблонов, админка шаблонов |
| Режимы A, B, C | Проверка чужого договора, калькуляторы, статьи |
| Вход: email+пароль и Яндекс ID | 2FA, вход через Госуслуги/VK |
| DOCX (PDF по возможности) | Электронная подпись, согласование с контрагентом |
| ИИ: чат, правки с diff, разбор реквизитов | Полноценный RAG на pgvector |
| Лимиты ИИ на пользователя и общий потолок | Тарифы, платежи |
| Docker Compose: web, api, postgres | Очередь, Redis, MinIO, Kubernetes, реплики БД (это `07-…`, после MVP) |
| Базовая безопасность (п. 7) | Полный аудит, пентест |

Принцип: **код пишем так, чтобы потом нарастить до `07-…` без переписывания** (stateless api, конфиг через env, UUID, миграции), но саму инфраструктуру пока не строим.

## 3. Стек MVP (упрощённый вариант из `04-architecture.md`)
- `apps/api`: Go (chi, pgx, sqlc, goose), сессии в Postgres (cookie httpOnly).
- `apps/web`: Next.js (App Router) + TypeScript + Tailwind, шрифты Inter + Manrope (кириллица).
- PostgreSQL в Docker. Генерация DOCX в Go; PDF через LibreOffice в контейнере api (если слишком долго, оставить только DOCX и записать в `STATUS.md`).
- Лимиты: в Postgres (таблица `usage_counters`), без Redis.
- ИИ: интерфейс `LLMProvider`, реализации: `gigachat` (по умолчанию для демо), `openrouter`, `stub` (для тестов и работы без ключа), позже `anthropic`.
- Нормы для ссылок: небольшой набор выдержек в `knowledge/*.md` (ТК РФ и ГК РФ, только нужные статьи), подставляются в промпт. ИИ обязан ссылаться только на них; остальное помечает «не подтверждено».

## 4. Дизайн: финальный, не MVP

### Референсы пользователя (лежат в `design/`)
- `v1.jpeg`: тёплый кремовый фон, плотные тёмные контуры, коралловые кнопки, цветные «таблетки»-теги, смелая геометрическая типографика. Берём: **кремовый фон и коралловый акцент**, цветные теги, характер заголовков. Жёсткие чёрные рамки и жёсткие тени НЕ берём (спорят со вторым референсом и с «воздухом»).
- `v2.jpg`: светлое мягкое приложение: боковая панель, скруглённые карточки, тонкие линии, мягкие тени, аккуратные таблицы с чекбоксами, Inter. Берём: **структуру кабинета и каталога** (список/сетка, карточки-«папки», хлебные крошки, счётчики).
- Моё решение: **светлая тема по умолчанию** (тёплый крем + белые поверхности), тёмная как переключатель, один контрастный тёмный блок на главной (раздел про ИИ) для футуристичности. Это меняет раздел про «чёрный» в `05-design-system.md`; приоритет у этого файла.

### Экраны (все делаем в финальном качестве)
1. **Главная**: большой заголовок, поле запроса с кнопкой ИИ, 6 карточек популярных документов, секции с закрепляющимися темами (п. 5), блок «ИИ» на тёмном фоне, FAQ, подвал.
2. **Каталог**: поиск, фильтр по категориям, карточки (как «папки» в v2), переключатель список/сетка.
3. **Конструктор**: слева шаги анкеты, справа лист документа, сверху переключатель режимов (Конструктор / По карточке / С ИИ), выезжающая панель ИИ.
4. **Вход/регистрация**: две колонки (форма + красивая иллюстрация/цитата), кнопки «Войти через Яндекс» и email.
5. **Кабинет**: боковая панель (Документы, Карточки, ИИ-чат, Настройки), таблица документов с чекбоксами и датами, карточки «недавние».
6. Пустые состояния, загрузки (скелетоны), ошибки, адаптив от 360px, доступность (контраст, фокус).

Для вёрстки Claude Code должен использовать навык **frontend-design**, если доступен. Перед завершением каждого экрана: поднять сайт, посмотреть скриншот и сравнить с референсами.

## 5. Анимация «закрепляющиеся темы» (по описанию пользователя)
Ссылка с Pinterest (`pin.it/1M7Fud2m4`) не открылась автоматически, поэтому реализуем по словам пользователя. **Если положить видео/скриншоты анимации в `design/anim/`, Claude Code должен сверить результат с ними.**

Поведение: при прокрутке вниз заголовок текущей темы **закрепляется вверху** экрана; когда подходит следующая тема, её заголовок **вытесняет** предыдущий.
Реализация:
- Каждая секция в обёртке; заголовок секции `position: sticky; top: <высота шапки>`; следующая секция естественно вытесняет его.
- Плавность: CSS scroll-driven animations (`animation-timeline: view()`), запасной вариант на IntersectionObserver; при желании GSAP ScrollTrigger.
- Эффекты: заголовок слегка уменьшается и тускнеет при закреплении, номер темы (01, 02, 03) сменяется.
- Только там, где это уместно: главная («Как это работает», «ИИ», «Безопасность», FAQ) и, возможно, шаги конструктора. В кабинете и каталоге не используем.
- Уважать `prefers-reduced-motion` (без анимации, обычный скролл).

## 7. Безопасность в MVP (минимум, обязателен)
- Пароли argon2id; cookie `HttpOnly; Secure; SameSite=Lax`; CSRF на изменяющих запросах; безопасные заголовки.
- Проверка владельца на каждом запросе документа/карточки (тесты на доступ к чужим данным).
- Rate limit на вход и ИИ. Ключи ИИ только в `.env` на сервере, `.env` в `.gitignore`.
- Данные пользователя в логи не пишем. В ИИ отправляем минимум (без паспортных данных).
- Дисклеймер «не заменяет юриста» на экранах с документами и ИИ.

## 8. Где взять ключи (инструкция для владельца)

### 8.1 Бесплатный ИИ (рекомендую GigaChat для демо)
1. Зайти на developers.sber.ru, войти через Сбер ID, создать проект «GigaChat API» и получить «Ключ авторизации».
2. Для физлиц действует Freemium-режим: бесплатные токены для генерации текста, а каждому новому пользователю по умолчанию подключается тариф Freemium; для физлиц значение scope: GIGACHAT_API_PERS.
3. С 17 июля 2026 года адрес подключения к API: https://api.giga.chat. Для запросов нужно установить сертификаты НУЦ Минцифры (в Docker-образе api добавить их в доверенные).
4. Вписать в `.env`: `LLM_PROVIDER=gigachat`, `GIGACHAT_AUTH_KEY=...`, `GIGACHAT_SCOPE=GIGACHAT_API_PERS`.

**Важная оговорка:** в соглашении для Freemium указано, что услуги можно использовать исключительно в личных некоммерческих целях, без права перепродажи или передачи учётных данных. Для локального демо это нормально. Для публичного сайта для всех нужно перечитать условия, возможно перейти на платный пакет/другого провайдера. Поэтому в коде провайдер сменяемый.

### 8.2 Запасной вариант: OpenRouter
Один ключ, OpenAI-совместимый API, модели с суффиксом `:free`. Лимит жёсткий: 50 запросов в день и 20 в минуту без платежей, 1000 в день после пополнения более $10. Для демо одному человеку хватит, для публики нет. `.env`: `LLM_PROVIDER=openrouter`, `OPENROUTER_API_KEY=...`, `OPENROUTER_MODEL=<id с :free>`.

### 8.3 Яндекс ID для входа
Зайти на oauth.yandex.ru → «Создать приложение» (платформа «Веб-сервисы») → Callback URI: `http://localhost:3000/api/auth/yandex/callback` → права: доступ к email и логину/имени. Получить ID и пароль приложения → `.env`: `YANDEX_CLIENT_ID=...`, `YANDEX_CLIENT_SECRET=...`. (Названия пунктов интерфейса Яндекса могут отличаться, ориентируйтесь на их документацию.)
До получения ключей приложение работает с `stub`-ИИ и входом по email: **ничто не блокируется**.

### 8.4 `.env.example`

## 9. Как запустить в Claude Code

**Вариант без терминала (рекомендуется):** приложение Claude (десктоп) → вкладка **Code** → окружение **Local** → выбрать папку проекта `constructor-site` → вставить промпт из шага 3 ниже. Шаги 1-2 (терминал) нужны только тем, кто запускает через CLI.
1. Открыть терминал, перейти в папку проекта: `cd ~/Documents/projects/constructor-site`
2. Запустить: `claude`
3. Вставить промпт:

```
Прочитай CLAUDE.md и docs/08-mvp-plan.md (он главный; docs/05 по палитре заменён разделом 4 из 08). Посмотри референсы в design/ (v1.jpeg, v2.jpg, и design/anim/ если есть). Пройди этапы M0-M10 по порядку, по циклу из docs/00-master-plan.md. Используй навык frontend-design для интерфейса. Работай без вопросов, пока не сработает условие остановки. Если нет ключей (ИИ, Яндекс), работай со stub и email-входом и запиши в STATUS.md, что нужно от меня. После каждого этапа: тесты, скриншот экрана, коммит, обновление STATUS.md.
```
4. Осторожный режим: «Выполни только этап M2 и остановись».
5. Если у Claude Code будет доступ к браузеру (Chrome), он сможет сам открыть сайт и сверить вёрстку со скриншотами. Дайте доступ, когда дойдёте до M2.

## 10. Критерии готовности MVP
- Сценарий из п. 1 проходит от начала до конца (e2e-тест).
- `make test` и `make lint` зелёные, `make dev` поднимает всё с нуля.
- Все экраны выглядят как финальный дизайн на 360, 768 и 1440 px.
