# 00. Главный план: как Claude Code проходит проект сам

Это входной файл. Прочитай его первым, потом `CLAUDE.md`, потом документы по списку ниже.

## Цель
Рабочий, безопасный, масштабируемый сайт-конструктор юридических документов РФ: режимы A (классический), B (по карточкам), C (ИИ). Бесплатный, вход обязателен для скачивания и сохранения.

## Прочитать перед стартом
1. `docs/02-product-spec.md` (что строим, решения владельца)
2. `docs/04-architecture.md` (стек, устройство)
3. `docs/05-design-system.md` (дизайн)
4. `docs/07-infrastructure-and-security.md` (нагрузка, надёжность, безопасность)
5. `docs/06-legal-and-risks.md` (риски)
6. `docs/03-roadmap.md` (этапы), `STATUS.md` (на каком этапе остановились)

## Цикл работы (повторять для каждого этапа)
1. Открой `STATUS.md`, найди первый невыполненный этап в `docs/03-roadmap.md`.
2. Напиши короткий план этапа в `STATUS.md` (3-8 строк).
3. Сначала тесты, потом код (для движка рендера, валидаторов, авторизации, ИИ-слоя это обязательно).
4. Запусти `make test` и `make lint`. Не переходи дальше при красных тестах.
5. Для UI: подними сайт, проверь страницу в браузере (скриншот), убедись, что она соответствует `05-design-system.md`.
6. Отметь этап `[x]` в `docs/03-roadmap.md`, допиши итог в `STATUS.md` (что сделано, что осталось, решения).
7. Сделай коммит: `step N: <суть>`.
8. Переходи к следующему этапу **без вопросов**, пока не сработает условие остановки.

## Условия остановки (остановись и спроси человека)
- Нужен секрет или ключ (ключ ИИ-API, SMTP, домен, доступы к серверу): создай `.env.example`, работай с заглушкой, запиши в `STATUS.md` раздел «Нужно от владельца».
- Нужно потратить деньги, купить сервер/домен, подключить платёжку.
- Юридическое решение (текст шаблона вне типовой практики, статус `reviewed`, политика ПДн в финальной редакции).
- Деструктивное или необратимое действие (удаление данных, force-push, смена схемы БД на проде).
- Этап 21 (юрист), 22 (сервер), 23 (HA): требуют человека и инфраструктуры. Подготовь инструкции и скрипты, дальше жди.
- Тесты не проходят после 3 серьёзных попыток исправления: опиши проблему в `STATUS.md` и остановись.

## Жёсткие правила
- Язык интерфейса: русский; код и комментарии: английский.
- Стек: Go + Next.js/TypeScript + PostgreSQL + Redis + MinIO. Отклонение только с записью причины в `docs/04-architecture.md`.
- Безопасность не откладывается на конец: авторизация объектов, валидация входов, лимиты закладываются сразу (`docs/07`, раздел 5).
- ИИ: ключи только на сервере; правки документа только структурным diff; ссылки на нормы проверять по `knowledge/`; квоты и потолок расходов обязательны, потому что сервис бесплатный.
- Не выдумывать нормы права. Шаблоны только со статусом `draft`, пока человек не подтвердил проверку юристом.
- Не коммитить секреты и `.env`.
- Не расширять объём сверх этапа: идеи записывай в `STATUS.md` → «Идеи на потом».
