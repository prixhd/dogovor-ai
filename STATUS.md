## Как запускать
- `make dev`: Postgres в Docker, api (`:8080`) и web (`:3000`) локально. Web проксирует `/api/*` на api.
- `make up`: всё в контейнерах (профиль `full`).

## Проверка
- `make test`: Go (юнит + интеграционные на Postgres: авторизация, CSRF, IDOR, квоты ИИ, утечки ПДн в промпт) и Vitest: зелёные.
- `make lint`: gofmt, go vet, golangci-lint (0 issues), ESLint, tsc: зелёные.
- `make e2e`: 2 сценария зелёные (нужен запущенный `make dev`).
- `next build`: продакшн-сборка проходит.

## Решения
- sqlc не используется: запросы написаны вручную на pgx (меньше шагов сборки для MVP). Записано в `docs/04-architecture.md`.
- Рендер документа только в Go; фронт получает готовые блоки. ИИ-правки хранятся отдельно от данных анкеты (`edits`: replaced/inserted/deleted по id блоков), поэтому анкету можно менять и после принятия правок.
- Лимиты и квоты в Postgres (`usage_counters`, `rate_buckets`) вместо Redis: сервис остаётся stateless.
- Лимит регистраций на IP настраивается `AUTH_REGISTER_PER_HOUR` (по умолчанию 10; в локальном `.env` поднят для e2e).

## Известные ограничения MVP (после MVP по `03-roadmap.md`)
- PDF работает только в Docker-образе api (там LibreOffice); локально без LibreOffice отдаётся понятная ошибка и DOCX.
- База норм `knowledge/`: пересказ 52 статей ТК/ГК, не официальный текст. Юрист должен сверить перед публичным запуском.
- Все 6 шаблонов в статусе `draft`.
- Нет подтверждения почты и сброса пароля (этап 4), удаления аккаунта (этап 19), шифрования паспортных полей на уровне приложения (этап 7).
- Stub-ИИ отвечает по правилам и базе норм; настоящие ответы и правки появятся с ключом GigaChat/OpenRouter. Адрес GigaChat (`https://api.giga.chat` + `/api/v1/chat/completions`) и OAuth-адрес нужно проверить с реальным ключом; оба переопределяются через env.
