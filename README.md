# договор.ai: конструктор юридических документов (MVP)

Веб-конструктор документов по российскому праву с тремя режимами:

- **A. Конструктор**: анкета по шагам, справа живой лист документа.
- **B. По карточке**: реквизиты сторон из сохранённых карточек или из вставленного текста (разбор делает ИИ).
- **C. С ИИ**: вопросы по нормам со ссылками на статьи и правки документа в виде diff с кнопками «принять / отклонить».

Шаблоны (все в статусе «черновик», не проверены юристом): трудовой договор, оказание услуг (ГПХ), наём квартиры, купля-продажа, заём с распиской, доверенность.

## Быстрый старт

Нужны: Go 1.27+, Node 24+, Docker.

```bash
cp .env.example .env
```

```bash
cd apps/web && npm install && cd ../..
```

```bash
make dev
```

Откройте http://localhost:3000. `make dev` поднимает Postgres в Docker, а API (`:8080`) и сайт (`:3000`) запускает локально с перезагрузкой. Сайт проксирует `/api/*` на API, поэтому cookie сессии работают без CORS.

Без ключей всё работает: ИИ отвечает через `stub`-провайдер (ответы собираются из базы норм, правки по шаблонным правилам), вход по почте и паролю. Кнопка «Войти через Яндекс» без ключей показывает понятное сообщение.

Чтобы остановить локальные dev-серверы: `make stop` (Postgres остаётся в Docker).

### Порты и частые проблемы

- Сайт: http://localhost:3000, API: http://localhost:8080 (проверка: http://localhost:8080/healthz), Postgres: 5432.
- `make dev` и `make up` занимают одни и те же порты, поэтому запускайте что-то одно. Если порт занят, команда сразу скажет, какой процесс его держит. Остановить: `make stop` (локальный dev) или `make down` (контейнеры).
- Ошибка `ENOENT ... .next/...` значит, что испорчен кеш сборки Next.js: `make stop && make clean`, затем запустите снова. Dev-сервер пишет в `.next-dev`, продакшн-сборка в `.next`, поэтому друг другу они больше не мешают.
- VPN не нужен. Нужен обычный интернет: при первом запуске Docker скачивает образы, npm и Go скачивают зависимости. GigaChat работает из РФ без VPN; OpenRouter из РФ может потребовать VPN.

### Всё в контейнерах

```bash
make up
```

Образ API включает LibreOffice, поэтому в контейнере работает экспорт в PDF. Локально без LibreOffice доступен только DOCX.

## Команды

| Команда | Что делает |
|---|---|
| `make dev` | Postgres + API + сайт для разработки |
| `make test` | Go-тесты (вместе с интеграционными на Postgres) и Vitest |
| `make lint` | gofmt, go vet, golangci-lint, ESLint, tsc |
| `make e2e` | Playwright: сценарий демо целиком (нужен запущенный `make dev`) |
| `make up` / `make down` | весь стек в Docker (сайт :3000, API :8080) |
| `make stop` | остановить локальные dev-серверы на 3000/8080 |
| `make clean` | удалить кеши Next.js (`.next`, `.next-dev`) |

Для e2e один раз установите браузер: `cd apps/web && npx playwright install chromium`. Прогоны регистрируют тестовые аккаунты; локально поднимите `AUTH_REGISTER_PER_HOUR` в `.env`, иначе после нескольких прогонов сработает лимит регистраций.

## Ключи (по желанию)

Подробно: `docs/08-mvp-plan.md`, раздел 8.

- **GigaChat**: `LLM_PROVIDER=gigachat`, `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`. Нужны сертификаты НУЦ Минцифры: путь к PEM в `GIGACHAT_CA_FILE` или установка в системное хранилище. Адреса API переопределяются через `GIGACHAT_URL` и `GIGACHAT_AUTH_URL`.
- **OpenRouter**: `LLM_PROVIDER=openrouter`, `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`.
- **Яндекс ID**: `YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, Callback URI `http://localhost:3000/api/auth/yandex/callback`.

## Устройство

```
apps/api      Go: chi, pgx, goose (миграции встроены в бинарь)
  internal/tmpl      формат шаблонов, валидатор, рендер, DOCX/PDF
  internal/ai        LLMProvider (stub, GigaChat, OpenRouter), база норм, маскирование ПДн
  internal/server    HTTP: сессии, CSRF, документы, карточки, ИИ, квоты
  internal/store     запросы к Postgres (всегда с проверкой владельца)
apps/web      Next.js 15 (App Router) + TypeScript + Tailwind 4
templates/    шаблоны YAML + фикстуры и золотые файлы (templates/testdata)
knowledge/    выдержки ТК РФ и ГК РФ, на которые ИИ обязан ссылаться
infra/        docker-compose
docs/         продукт, архитектура, дизайн, безопасность, планы
```

### Как добавить шаблон

1. Создайте `templates/<slug>.yaml` по образцу существующих (роли, шаги, поля, тело из блоков).
2. Добавьте фикстуру `templates/testdata/<slug>.json`.
3. Сгенерируйте золотой файл: `cd apps/api && go test ./internal/tmpl -run TestGolden -update`, затем прочитайте его глазами.
4. Каждая статья, упомянутая в шаблоне, должна быть в `knowledge/`: это проверяет тест.
5. Статус только `draft`, пока юрист не проверил шаблон.

## Безопасность (MVP)

Пароли argon2id; сессии в Postgres (в БД хранится только хеш токена); cookie `HttpOnly; SameSite=Lax` (и `Secure` на https); CSRF: проверка Origin + токен; лимиты на вход, регистрацию и ИИ; проверка владельца на каждом документе и карточке (тесты IDOR); в ИИ не уходят паспортные данные, телефоны, СНИЛС и почта; логи без содержимого документов.
